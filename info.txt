ОПИСАНИЕ ПРОЕКТА (заметка для себя / для Claude в новой сессии)
====================================================================

Это папка с мини-играми на чистом HTML/CSS/JS — без сборки, без npm,
без интернета (кроме шрифта Google Fonts в index.html — не критично,
если офлайн, шрифт просто заменится на системный). Каждая игра — один
самостоятельный .html файл, который можно открыть двойным кликом в
любом браузере.

Структура папки
----------------
- index.html            — главная страница-хаб со списком игр (карточки)
- build_house_game.html  — игра "Стройка": собираем домик у моря,
                            перетаскивая детали (крыша, стены, окна,
                            дверь, дымоход), в конце — конфетти и
                            декор двора (ёлочка, цветочек)
- build_house_game-old.html — черновая/старая версия "Стройки", оставлена
                            на всякий случай, в index.html не используется
- soap_bubbles_game.html — игра "Мыльные пузыри" (см. подробности ниже)
- info.txt               — этот файл

Игра "Мыльные пузыри" (soap_bubbles_game.html)
-----------------------------------------------
Переделана из Unity-проекта C:\Unity\BalloonPop (там были шарики-
префабы Ball1..Ball7 с лопаньем по клику). В HTML-версии картинки не
используются вообще — пузыри рисуются CSS-градиентами (radial-gradient,
блик сверху-слева), выглядят как мыльные пузыри разных цветов и разного
случайного размера.

Механика:
- Пузыри вылетают снизу вверх, каждый со своей скоростью, частотой и
  амплитудой покачивания (не синхронно — специально, чтобы не было
  ощущения "трясущегося экрана").
- Спавн учитывает размер конкретного пузыря — он никогда не появляется
  так, чтобы вылезти за левый/правый край экрана.
- Клик/тап по пузырю лопает его: пузырь исчезает, разлетаются
  разноцветные "конфетти"-осколки (через requestAnimationFrame, у
  каждой частицы свои независимые переменные — важно было объявлять их
  через let в цикле, иначе частицы "зависали" на экране и не исчезали).
- Звук хлопка играет всегда. Дополнительно: обычные пузыри — детский
  смех (detskiysmeh.mp3), красный пузырь (самый яркий, #DF1020/#FF6B6B —
  цвет подобран под реальный красный шарик, который прислал пользователь)
  — звук "пуканья" (pukaet.mp3) вместо смеха. Оба звука встроены прямо в
  html как base64 (data:audio/mpeg;base64,...), файл получается ~78 КБ,
  ничего скачивать не нужно.
- Звук проигрывается через `new Audio(src)` на каждый клик (не через
  cloneNode — не везде надёжно), плюс "разблокировка" аудио по первому
  тапу на кнопку старт (для мобильных браузеров, которые блокируют
  автозвук до жеста пользователя).
- Если пузырь долетел до верха и не лопнут — считается "улетевшим".

Интерфейс:
- Нижняя панель (полупрозрачная, с отступом под safe-area на телефонах):
  слева — компактные счётчики в столбик (Лопнуто / Улетело / Всего),
  справа — две круглые зелёные кнопки: play/pause (иконка меняется) и
  рестарт (закрученная стрелка). Рестарт работает в любом состоянии
  игры (даже на паузе), очищает экран от пузырей и осколков, обнуляет
  счётчики и сразу запускает игру заново.
- Заголовка и кнопки "назад к играм" нет специально — переход назад
  делается обычной кнопкой браузера "Назад".
- Верстка на vmin/flex, рассчитана на то, что будут играть и на
  телефоне (отзывчивая, touch-friendly, без скролла/зума страницы).

Про git и GitHub Pages (обновлено — теперь есть remote!)
-----------------------------------------------------------
Локальная ветка называется master, репозиторий подключён к GitHub:
  https://github.com/ssadovsky/kids-games.git
На GitHub дефолтная ветка — main (не master!). Пушить руками так:
  git push origin master:main
(либо переименовать локальную ветку в main, если удобнее — main <- master).

Сайт (GitHub Pages) публикуется автоматически из main, /(root), живёт
тут: https://ssadovsky.github.io/kids-games/
Никаких лишних действий в настройках GitHub Pages делать не нужно —
просто закоммитить и запушить в main, через 30-60 сек изменения на сайте.

Переименование папки на диске НИКАК не влияет на git — вся история
хранится внутри .git рядом с файлами и не привязана к пути/имени папки.
После переименования просто нужно заново подключить папку к Claude
(кнопка "Add folder" в приложении, или начать новую задачу с выбором
этой папки) — сама история и файлы никуда не денутся.

ВАЖНО: пуш из песочницы Claude (изолированная Linux VM на компьютере
пользователя, через которую Claude работает с этой папкой) НЕ РАБОТАЕТ —
там нет сохранённых логинов GitHub. Claude может закоммитить локально,
но `git push`/`git pull` пользователь должен выполнять сам, из обычного
терминала/GitHub Desktop на своей машине.

Если открываешь в Visual Studio 2022: для этих файлов (чистый HTML/
CSS/JS) она не обязательна и довольно тяжеловесна — подходит скорее
для .NET/Unity-проектов. Для просмотра git-diff и правки html удобнее
VS Code (Live Server + встроенный git diff) или просто git-клиент
(GitHub Desktop, gitk, `git diff` в консоли). Но если VS2022 уже
установлена и привычна — открыть папку как "Open Folder" в ней тоже
можно, диффы по файлам она показывает нормально.

ANDROID-ПРИЛОЖЕНИЕ (TWA / Bubblewrap) — деплой через GitHub Actions
====================================================================
Добавлено в сессии от 2026-09-02. Суть: сайт (GitHub Pages) обёрнут в
"тонкую" Android-оболочку (Trusted Web Activity) — приложение просто
открывает live-сайт в Chrome на весь экран. Контент игр НЕ зашит внутрь
apk/aab — любой коммит в GitHub Pages сразу виден в уже установленном
приложении, пересобирать apk/aab для правок игр НЕ нужно. Пересборка
нужна только если меняются: иконка, package id, twa-manifest.json,
или сам workflow-файл.

Технология выбрана осознанно: TWA + Bubblewrap (официальный CLI от
команды Chrome в Google), НЕ Capacitor/Cordova/Unity — потому что задача
была именно "обернуть готовый сайт", а не писать нативные фичи.

Файлы, которые за это отвечают
-------------------------------
- manifest.json              — Web App Manifest (PWA). Название, иконки,
                                start_url, theme_color и т.п.
- sw.js                       — service worker, кэширует игры для офлайна
                                (регистрируется из index.html)
- icon-192.png, icon-512.png,
  icon-512-maskable.png       — иконки приложения (сгенерированы, можно
                                заменить на свои тех же размеров/purpose)
- twa-manifest.json           — конфиг для Bubblewrap: package id
                                (com.ssadovsky.kidsgames), host
                                (ssadovsky.github.io), цвета, display
                                mode (сейчас "fullscreen" — прячет
                                статус-бар и панель навигации Android),
                                путь и алиас ключа подписи.
- .github/workflows/build-twa.yml — GitHub Actions workflow. Ставит JDK
                                17 + Android SDK + Node + Bubblewrap CLI
                                на сервере GitHub (там есть интернет, в
                                отличие от песочницы Claude), собирает
                                подписанные app-release-bundle.aab и
                                app-release-signed.apk, кладёт их как
                                скачиваемый Artifact.
- .well-known/assetlinks.json — для Digital Asset Links (см. ниже).
  ВНИМАНИЕ: этот файл лежит и тут для справки, но реально он должен
  отдаваться с КОРНЯ домена ssadovsky.github.io, а не из /kids-games/
  (см. отдельный репозиторий ниже).
- .gitignore                  — исключает SECRETS_DO_NOT_COMMIT/ и
                                любые *.keystore/*.jks от коммита.
- ANDROID_BUILD.md            — почти то же самое, что этот раздел,
                                более сжато, лежит в корне репы отдельным
                                файлом.

Как пересобрать apk/aab
-------------------------
GitHub → вкладка Actions → workflow "Build Android app (TWA /
Bubblewrap)" → Run workflow. Либо срабатывает само при пуше коммита,
который трогает twa-manifest.json / manifest.json / сам workflow-файл.
Через ~2 минуты в этом же прогоне внизу — Artifacts →
kids-games-android-build → внутри app-release-bundle.aab (для Google
Play Console) и app-release-signed.apk (можно поставить на телефон
напрямую, скопировав файл, имя файла переименовывать можно свободно —
на установку не влияет, Android определяет приложение по package id
внутри, а не по имени файла).

GitHub Secrets (Settings → Secrets and variables → Actions) — уже
добавлены пользователем, нужны для подписи сборки:
  ANDROID_KEYSTORE_BASE64
  BUBBLEWRAP_KEYSTORE_PASSWORD
  BUBBLEWRAP_KEY_PASSWORD  (тот же пароль, что и KEYSTORE_PASSWORD —
                            keystore в формате PKCS12, там store и key
                            пароль всегда одинаковые)

Сам keystore-файл и пароли в открытом виде — ТОЛЬКО в
SECRETS_DO_NOT_COMMIT/ (в .gitignore, в GitHub никогда не попадёт).
Если этот файл потерять — обновлять уже опубликованное в Play Console
приложение тем же package id станет невозможно, там всё написано
подробно, включая SHA256-отпечаток сертификата.

Грабли, которые уже наступлены и починены (чтобы не наступать снова)
-----------------------------------------------------------------------
1. `bubblewrap update` в CI зависал и падал с exit code 130 — он
   интерактивно спрашивает "поставить ли JDK?" и "versionName?", а в
   Actions нет ввода с клавиатуры. Починено: перед update/build workflow
   заранее пишет ~/.bubblewrap/config.json (jdkPath/androidSdkPath из
   JAVA_HOME/ANDROID_HOME, которые сама же Actions ставит парой шагов
   раньше) + флаг --skipVersionUpgrade + на всякий случай пустые строки
   на stdin (accept defaults) как подстраховка от других таких вопросов.
2. Push из песочницы Claude не работает (см. раздел про git выше) —
   коммитить оттуда можно, пушить — только руками пользователем.
3. `build_house_game.html` не имел <meta name="viewport"> — из-за этого
   мобильные браузеры рендерили страницу как десктопную (980px) и
   потом сжимали, вылезала полоска сбоку. Починено — добавлен тег, как
   в index.html/soap_bubbles_game.html.

Digital Asset Links (чтобы приложение выглядело "нативно", без адресной
строки Chrome сверху)
-----------------------------------------------------------------------
Нужен файл https://ssadovsky.github.io/.well-known/assetlinks.json
(строго в КОРНЕ домена, не в /kids-games/). Для этого создан ОТДЕЛЬНЫЙ
репозиторий на GitHub: https://github.com/ssadovsky/ssadovsky.github.io
(имя репозитория обязано быть ровно "<логин>.github.io" — так работает
GitHub Pages для пользовательских сайтов). Там всего 2 файла:
  .nojekyll                  — пустой файл, ОБЯЗАТЕЛЕН. Без него GitHub
                                Pages прогоняет всё через Jekyll, а
                                Jekyll по умолчанию игнорирует папки,
                                начинающиеся с точки (.well-known) —
                                файл отдавал 404 без этого.
  .well-known/assetlinks.json — тот же контент, что и копия в этом
                                репозитории (kids-games), содержит
                                package_name + sha256_cert_fingerprints
                                ключа подписи.
Уже сделано и проверено — https://ssadovsky.github.io/.well-known/assetlinks.json
отдаёт корректный JSON. Если после публикации в Google Play появится
Play App Signing (у Google свой сертификат поверх твоего upload-ключа) —
туда же вторым объектом добавить SHA256-отпечаток ИЗ Play Console
(Setup → App integrity), иначе после первой публикации в Play строка
адреса в Chrome может вернуться.

Google Play Console
----------------------
Аккаунт разработчика у пользователя уже есть (оплачен ~2016, разовый
платёж, не истекает). Package id — com.ssadovsky.kidsgames — ПОСЛЕ
первой загрузки .aab в Play Console сменить будет нельзя. Если нужен
другой — менять поле packageId в twa-manifest.json ДО первой публикации.

Известные нерешённые мелочи (осознанно оставлено как есть)
-----------------------------------------------------------
- В игре "Мыльные пузыри" можно поставить игру на паузу, когда экран
  полон пузырей, и спокойно лопать их без спешки (пауза останавливает
  анимацию/спавн, но не блокирует клики-попадания). Пользователь в курсе,
  решил не чинить, "посмотреть как пойдёт". Если попросит — искать в
  soap_bubbles_game.html обработчик паузы и добавить туда игнор кликов
  по пузырям, пока флаг паузы включён.
- На Samsung Galaxy S25 Ultra (и вероятно других телефонах с вырезом
  фронтальной камеры) в альбомной ориентации в fullscreen-режиме
  приложения видна тонкая серая полоса сбоку экрана — Android резервирует
  место под вырез камеры. Это известная нерешённая шероховатость самого
  Bubblewrap/androidbrowserhelper (см. открытые issue в их GitHub:
  GoogleChromeLabs/bubblewrap #901 и #722), готового поля в
  twa-manifest.json для этого нет. Можно попробовать патчить сгенерированный
  AndroidManifest.xml прямо в CI (добавить шаг между `bubblewrap update`
  и `bubblewrap build`, дописать android:windowLayoutInDisplayCutoutMode),
  но это неофициальный путь без гарантий — пользователь решил оставить
  как есть, это чисто косметика, на геймплей не влияет.
